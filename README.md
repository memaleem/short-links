# קיצור קישורים - מערכת אישית

מערכת לקיצור קישורים עם דומיין משלך: קישור אחד יציב, יעד שאפשר להחליף בכל רגע, ספירת לחיצות, קוד QR, בונה UTM ופיקסל מעקב.

בנוסף יש דף "המפה" - עמוד אחד שמרכז את כל הקישורים והמערכות שלך, בכתובת סודית.

## ממה זה בנוי

- אתר Next.js שרץ בחינם על Vercel
- מסד נתונים Supabase (גם בחינם)
- שער כניסה בסיסמה אחת (בלי ניהול משתמשים)

## התקנה - שלב אחרי שלב

### 1. מסד הנתונים (Supabase)

1. נרשמים ב-[supabase.com](https://supabase.com) ופותחים פרויקט חדש.
2. בתפריט הצד: **SQL Editor** - מדביקים את כל התוכן של הקובץ [supabase/schema.sql](supabase/schema.sql) ולוחצים **Run**.
3. בתפריט הצד: **Settings ← API** - בשדה **Exposed schemas** מוסיפים את `links` לרשימה (ליד public) ושומרים. בלי זה השרת לא יצליח לגשת לטבלאות.
4. מאותו עמוד מעתיקים שני ערכים: **Project URL** ואת המפתח **service_role** (לא anon).

### 2. משתני סביבה

מעתיקים את `.env.example` לקובץ בשם `.env.local` וממלאים את הערכים - ההסברים בתוך הקובץ.

להפקת המחרוזות האקראיות (AUTH_SECRET ו-HUB_SECRET) אפשר להריץ בטרמינל:

```bash
openssl rand -hex 32
```

### 3. הרצה מקומית (בדיקה)

```bash
npm install
npm run dev
```

נכנסים ל-http://localhost:3000 - אמור להופיע מסך כניסה עם הסיסמה שהגדרתם.

### 4. העלאה לאוויר (Vercel)

1. מעלים את התיקייה לריפוזיטורי משלכם בגיטהאב (פרטי מומלץ).
2. נרשמים ב-[vercel.com](https://vercel.com) עם חשבון הגיטהאב, לוחצים **Add New ← Project** ובוחרים את הריפוזיטורי.
3. לפני הלחיצה על Deploy: פותחים **Environment Variables** ומזינים את כל המשתנים מ-`.env.local`.
4. לוחצים **Deploy**.

### 5. חיבור הדומיין הקצר

1. ב-Vercel: **Settings ← Domains** - מוסיפים את הדומיין (למשל `link.mydomain.co.il`).
2. אצל ספק הדומיין מוסיפים רשומת CNAME שמצביעה לפי ההוראות ש-Vercel מציג.
3. מוודאים ש-`NEXT_PUBLIC_SHORT_HOST` ב-Vercel זהה לדומיין הזה, ועושים Redeploy אם שיניתם.

## שימוש יומיומי

- **לוח הבקרה:** נכנסים לדומיין, מזינים את הסיסמה, ומשם יוצרים ועורכים קישורים.
- **קישור קצר:** `https://<הדומיין>/<slug>` - כל כניסה נספרת ומתועדת (מדינה, מכשיר, דפדפן, מקור).
- **דף המפה:** `https://<הדומיין>/h/<HUB_SECRET>` - פתוח לצפייה בלי סיסמה (למי שמכיר את הכתובת); עריכה דורשת את סיסמת לוח הבקרה. אפשר למלא אותו ידנית מהדף עצמו, או להזין רשימה ראשונית עם `node scripts/seed-hub.mjs` אחרי עריכת הדוגמאות שבקובץ.

### מעקב קמפיינים

אפשר להשתמש באותו קישור קצר בכמה קמפיינים ולראות פילוח לכל אחד, בלי ליצור קישור נפרד. מוסיפים פרמטרים לקישור בכל מקום שבו מפרסמים אותו:

```
https://<הדומיין>/<slug>?utm_campaign=ep12&utm_medium=cpc
```

בעמוד הקישור יופיעו אז שני פילוחים נוספים: **קמפיין** ו**ממומן מול אורגני**.

- נשמרים רק פרמטרי מעקב: כל `utm_*`, מזהי קליק של רשתות פרסום (`gclid`, `fbclid`, `msclkid` וכו') ו-`ref`/`src`. שאר הפרמטרים בכתובת נזרקים ולא מגיעים למסד.
- לחיצה מסווגת כ**ממומנת** אם יש בה מזהה קליק של רשת פרסום, או אם `utm_medium` הוא ערך ממומן מוכר (`cpc`, `ppc`, `paid` וכדומה).
- הפרמטרים האלה משמשים למדידה בלבד ולא נדחפים ליעד. ה-UTM שמוגדר על הקישור עצמו בלוח הבקרה ממשיך לעבוד כרגיל.

> **שדרוג ממסד קיים:** אם הרצתם את `schema.sql` לפני שהתכונה הזו נוספה, צריך להריץ פעם אחת את [supabase/migrations/001-click-params.sql](supabase/migrations/001-click-params.sql) ב-SQL Editor. עד שזה יקרה, הלחיצות ימשיכו להיספר רגיל - פשוט בלי פילוח הקמפיין.

## חשוב לדעת

- המפתח service_role נותן שליטה מלאה במסד הנתונים - לא לשתף אותו ולא להעלות את `.env.local` לגיט (הוא כבר ברשימת ההתעלמות).
- כל המערכת שלך נפרדת לגמרי: הפרויקט בסופרבייס, החשבון ב-Vercel, הדומיין והסיסמאות - הכל שלך.
